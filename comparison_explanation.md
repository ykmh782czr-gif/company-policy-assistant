Across the same ten questions and 98 company policies, rules-based search answered 4/10 correctly, while both LLM approaches answered 10/10 correctly using Gemini 3.5 Flash Lite after the primary model exhausted its daily quota. Keyword search averaged 0.00027 seconds and used no model tokens, but five responses quoted an unrelated policy and one missed the dress-code policy. Both LLM methods correctly abstained on the three questions absent from the database. Manual review found no fabricated policy statements in this run; the keyword method’s unrelated quotations were still incorrect answers. These ten examples demonstrate observed behavior, not a general hallucination rate.

For this small policy database, I prefer the LLM without a vector index because it considers every policy, requires less retrieval infrastructure, and matched the vector method’s accuracy. Its mean response time was 1.41 seconds versus 2.36 seconds for vector retrieval, including retries; median times were 0.83 and 1.38 seconds. However, vector retrieval used only 1,694 generation tokens across ten questions compared with 27,969 without retrieval, a reduction of about 94%, making it attractive as the database grows. The vector approach also requires query embeddings and an offline index: embedding-token usage was not reported by the API, and index construction is excluded from these measurements. Quota delays affected this run, so the timings should not be treated as a controlled speed benchmark.
